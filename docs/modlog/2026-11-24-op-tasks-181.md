## Effect tasks: the op tasks ours did not count, and the glow starts inside ops 0x75 / 0xa3 (2026-11-24)

<!-- dll-build: 30261102_0 -->

Modlog-gaps item 181 (split from 172): tasks retail's scheduler ops make that ours had no node for in the walk, so a
child's first update that runs one of these ops did not send the walk back to its parent (row 172's rule).

- Op 0x7f (0x1005ba4b; ours called it a no-op): on actor1 through its dolls (FUN_10062770) a child task (FUN_100613d0
  -> FUN_100610c0 -> FUN_10074790, vtable 0x1032cd30) ramps the actor's +0x668 (vtable +0x38 / +0x34 = FUN_100a4870
  / FUN_100a4860) to u32 @8 over trunc(dur x speed) ticks. Nothing on a character actor reads +0x668 (the only other
  readers, FUN_100acba0 / FUN_100acf90, are the door class's part table), so only the task's link is kept. 15 uses in
  9 files (5036 yam_, 5069 kam_, 5070 / 5071 jir_, 51230 eld_, 51316..51341 pro_).
- Op 0x04 / 0x81 (0x1005a03c): the path (kind 6, the name @8, cached in the op's +0xc) must be found (FUN_10071060).
  FUN_1003c8a0 deletes the last camera task (DAT_1047cb30, vtable +0x18) and, unless the path counts one camera
  (+0x70 = payload 0x10: low byte keys + bit 19 current + bit 20 follow) and trunc(dur x speed) is 0 (FUN_1003c970
  sets it at once), makes the new one (FUN_1003cc80 -> FUN_10074740, then FUN_100747d0 makes it the scheduler's
  child). In any scheduler, not only an event's. The delete needs no node: whatever it does to the walk's next, the new
  link sets it to the new task; with no new task the old one was not the walk's next unless it sits right after the
  scheduler, and its next is then where the walk goes either way.
- Ops 0x75 / 0xa3 (0x1005be14 / 0x1005bef4): FUN_100d5f10 (show) and FUN_100d60e0 (hide) set the hide byte and call
  FUN_100d5fe0 / FUN_100d6180, which start `!w01` / `!w11` / `!w02` / `!w12` with FUN_100cef00 -> FUN_10056c70: the
  glow scheduler starts inside the op and runs its first update at once. Ours handed the op to the client, which
  queued the glow for the next tick. Now `Effects::glow_in_op` starts it in the op (on when actor1 is engaged and
  not invisible, +0x128 bit 6, else off), behind any call still waiting on the actor's files; the client only sets the
  hide byte (`WeaponOp::glow` false). Op 0x75's timed hide (FUN_10061960) links its timer (FUN_10074790) before its
  hide starts `!w02`, as ours now does. The timer's end show (FUN_10061920, in the timer's destructor) still goes
  through the client.
- Closed by census (`dat::sched::census::op_task_census`): ops 0x1a (FUN_10085e40 makes an actor when the named one is
  missing; DAT_1047e840 is never written, only read at 0x10085e40), 0x81, 0x82 and 0x83 are in no DAT.
