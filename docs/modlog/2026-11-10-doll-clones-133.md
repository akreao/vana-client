## Effect generators: data 0x80, dolls move no clones, the view matrices' users (2026-11-10)

Modlog-gaps item 133 ("Effect generators: data 0x80; DAT_10443fe4 +0x28; the view matrices' purposes", MODLOG "Not
traced: data 0x80; ..."). Addresses are Steven's FFXiMain.dll, read in the decompile and the disassembly.

- Data 0x80 is where a clone keeps the task FUN_10062d50 asks for, and nothing ever puts one there. The generator
  object is the chunk's data + 0x70 (FUN_10047ce0 turns the four stream offsets at +0xe0..+0xec into pointers by
  adding object + 0x60), so data 0x80 is +0xf0. A template never has it read. A clone (CMoGeneratorClone, class
  record 0x1032b100, size 0xfc; constructor FUN_100536c0) gets +0xf0 = 0 (0x100536f9), +0xf4 = the template's +0x14
  and +0xf8 = 0; the copy FUN_10053450 stops at +0xec. The only reader of clone +0xf0 is FUN_10062d50 (0x10062d95).
  A scan of every store to a +0xf0 displacement in the listing finds no other on a generator: the rest are element
  scales, actor fields and unrelated classes. Scheduler op 0x02 does record its task on an attached clone, but at
  +0x64 (FUN_1005e0f0 on clone + 0x30: [+0x34]), the field the weather object uses for its own clones. The small
  values in the files (0x100, 0x211, 0x40a) are whatever the authoring tool left.
- So the doll ops move no clones. Ops 0x15 / 0x16 / 0x22 / 0x23 (0x10058acd, 0x10058974, 0x100589cc) build the doll
  (FUN_100abea0: the actor's place, sizes and 0x30 points; it links nothing over), call FUN_10062d50(task; actor,
  doll, slot), which walks the actor's actor1 (+0x68) or actor2 (+0x6c) list for CMoGeneratorClones whose +0xf0 is
  the task and so finds none, and put the doll in the task's slot (FUN_10062830 / FUN_10062880). Ops 0x17 / 0x18
  (0x10058b9e / 0x10058c08) do the same back to the actor. What the task started before the op stays on the actor;
  only what it starts afterwards attaches to the doll, and stays there after the op that puts the actor back.
- This corrects "Dolls take only their task's clones" (2026-10-23) and the later notes built on it, which read
  the +0xf0 test as working. Both bugs those entries fixed stay fixed, as neither needs a move: a trust's appearance
  scheduler no longer takes the cast's sparkles, and nothing takes Shantotto II's orbs. Weapon skill 35595 shows the
  difference: `main` starts the endless g000 on the pair and then dolls the target (op 0x23); with the move g000
  went to the doll, `st44`'s stop on the pair missed it and it glowed until the target despawned. As retail has it,
  g000 stays on the target and `st44` ends it at tick 145.
- Ticks a frame (DAT_10443fe4 +0x28, now DAT_104568fc +0x28): closed by item 130 (the 4-frame average in whole
  ticks, at least the divisor and at most 20, FUN_10011a00; FUN_10014cf0 = max(1, it)).
- The view matrices (FUN_1006a180 on DAT_1047bfa8) and who reads them:
  - +0xb50, the device's VIEW: the elements' view position and draw matrix (FUN_10044f10, FUN_10045190,
    FUN_100467e0), the view-box gate (FUN_100496f0), restoring VIEW after a pass (FUN_100472f0, FUN_10054f80), the
    sky dome (FUN_1003db60, with the translation zeroed).
  - +0xb90, its rotation: camera-relative elements (flag 4), the default of the selector FUN_10045c50 (flags 0x2000
    / 0x4000 clear), the emission (FUN_1004e8d0 through FUN_10052900), the batched particles (FUN_10063c80).
  - +0xd10 (world y kept as view y, yaw only): selector 1 only. 103 generators in all DATs, 62 of them billboards,
    which do not use the matrix.
  - +0xd50 (world x / z kept, the view's image of world y): selector 2, the common one, 13,588 generators. The sky
    dome also copies it into WORLD and overwrites that with the identity in the next call (0x1003dc53 / 0x1003dc69):
    a dead store.
  - +0xc10 = d10 x d50: selector 3, which no generator in any DAT has (census
    `dat::generator::tests::view_sel_census`); attach modes 7 / 8 (FUN_1003be10) and emission op 0x6a.
  - The four inverses (+0xbd0, +0xc50, +0xc90, +0xcd0) are built every frame and read by nobody.
  Ours already builds b90 / d10 / d50 / c10 the same way (render/effects.rs `view_set`) and selects them the same
  (effects.wgsl); nothing to change there.
- Ours now: scheduler ops 0x15 / 0x16 / 0x22 / 0x23 make the doll and ops 0x17 / 0x18 put the actor back without
  touching any clone (`move_clones` is gone).
