fx/sound.rs (`nearest`). Closes the "Effect sound" open line (MODLOG L3633, modlog-gaps item 114). Addresses are
Steven's FFXiMain.dll.
- Emission op 0x6b (FUN_1004e8d0 case 0x100501c9): +0x198 = the Sph; the position = eye (FUN_10015250 + 0x60) +
  FUN_10056160(Sph + 0x30, out, eye). FUN_10056160 walks the segment pairs (block +0x14: count, then (a, b) u32 pairs,
  low 24 bits each) over the points (block +0x10, 0x20 bytes, x y z r from +0x10), keeps the smallest result of
  FUN_10055f60 (strict <, from 1e9) and its offset.
- FUN_10055f60(A, B, out, P), read from the asm: L = |A - B|, n = normalize(A - B) (math vt+0xa0 -> +0xa4 =
  0x1006d5d0: a zero vector stays zero), t = clamp(n . (P - A), -L, 0), Q = A + n t, out = Q - P, D = |out|. When L > 0:
  s = -t / L, r = (1 - s) rA + s rB, out = unit(out) x max(D - r, 0), returned. When L = 0: out = A - P, no radius.
- Ours matched except the L = 0 case, which applied A's radius; now it does not. Census of Steven's install: 100 Sph
  chunks, one with a zero-length segment (DAT 204 `kawa`, segment 0).
- FUN_10053890(hard) (the soft / hard stop; the older DLL's FUN_100528e0): clears +0xd8 bit 0x800; with a driver task at
  +0xa8, hard deletes it (vt+0x18(1)), soft sets +0xdc bit 0 and task +0x14 = 1. The +0xa8 task (0x3d bytes, vtable
  0x1032b654, made by FUN_10053370 / FUN_100531d0 at start / restart, +0x18 / +0x34 / +0x38 the generator handle, +0x1c
  0x4d670000) is what runs the generator each frame: FUN_10054220 returns at once while +0xdc bit 0 is set and calls
  fx_gen_update_emit only while +0x14 is 0; when that reports the life over it sets +0x3c and deletes itself once the
  generator has no references. A restart (FUN_10053370) of a soft-stopped generator clears +0x14 and bit 0 and sets
  0x800 again. fx_gen_update_emit itself also returns at once with +0xdc bit 0 (clones run by ops 0x25 / 0x33 / 0x46
  freeze too).
- The template-wide stop FUN_10053a00 (soft): FUN_10053890(0), then elapsed = life when life is not 0 and not yet
  reached, deleting the generator when nothing references it. As ours (`stop_generator`).
- A soft stop does not end persistent sound elements: the sound element's per-frame FUN_100364e0 never reads the
  generator's +0xdc, and its persistence (vtable 0x1032a930 +0x40 = FUN_10036770) is the owner's FUN_100539e0 (+0xd8

  generator is hard-stopped or deleted. Ours matches (gen_persistent is fixed at the element's start).
